PHASE A — CRITICAL FIXES (v0.2) — Address the 4 verified gaps
================================================================================

The review identified 4 HIGH-priority gaps where implementation either could
not be verified or was suspected missing. We know these are actually implemented
but need to be made more visible and testable.

A1. DIRTY FILE GUARD — VERIFY & SURFACE (HIGH)
----------------------------------------------
Status  : IMPLEMENTED (agent.py _execute_tool_with_confirmation, tools.is_file_dirty)
Gap     : Copilot could not find it because it's inside agent.py which is large
Action  :
  1. Extract dirty file check into a standalone tools.py method: check_dirty(path)
  2. Add dedicated test: test_dirty_file_blocks_write_without_approval
  3. Add inline docstring: "Dirty File Guard — blocks write if uncommitted changes"
  4. Document in ULTRON.md convention section
Files   : ultron/tools.py, tests/verify_agent.py
Priority: HIGH — this is a core safety promise

A2. PROVIDER FALLBACK LOGIC — MAKE EXPLICIT (HIGH)
---------------------------------------------------
Status  : PARTIALLY IMPLEMENTED (registry.py get_working_provider + handle_failure)
Gap     : The fallback path exists but is only triggered from REPL, not from
          the agent loop when a streaming call fails mid-turn
Action  :
  1. Add try/except around model.chat() in agent.py run() loop
  2. On ProviderError/ConnectionError, call provider_registry.handle_failure()
  3. If fallback available, switch and retry the same turn
  4. If no fallback, set mode to "ask" and continue read-only
  5. Add test: test_provider_failure_triggers_fallback
Files   : ultron/agent.py, ultron/providers/registry.py, tests/test_providers.py
Priority: HIGH — promised feature, critical for reliability

A3. CONTEXT WINDOW AUTO-MANAGEMENT (MEDIUM)
-------------------------------------------
Status  : 50k char budget enforced in context.py but not provider-aware
Gap     : No warning when approaching provider's actual token limit
          No auto-switching to larger context model
Action  :
  1. In _get_system_message(), estimate token count via provider.count_tokens()
  2. If > 75% of provider's context_window, warn user in console
  3. If > 90%, offer to compress: trim pinned files or clear old turns
  4. Add /context-status command showing current usage vs limit
Files   : ultron/agent.py, ultron/context.py, ultron/repl.py
Priority: MEDIUM — important for long sessions

A4. STRUCTURED SESSION LOGGING (HIGH)
--------------------------------------
Status  : execution_logs exists in tools.py but is in-memory only (lost on exit)
Gap     : No persistent audit trail of what Ultron did across sessions
          Metrics collector writes task summaries but not granular tool calls
Action  :
  1. Create ultron/session_log.py with structured JSONL logger
  2. Log every tool call: {timestamp, tool, args_summary, result, exit_code}
  3. Log every model call: {timestamp, provider, model, tokens_in, tokens_out}
  4. Store at ~/.ultron/logs/<workspace_hash>/session_YYYYMMDD.jsonl
  5. Add /logs --detail flag to show tool-level events
  6. Feed into /metrics for richer analytics
Files   : ultron/session_log.py (new), ultron/agent.py, ultron/repl.py
Priority: HIGH — builds user trust ("I can see exactly what Ultron did")

PHASE B — ARCHITECTURE IMPROVEMENTS (v0.3)
================================================================================

B1. PLUGIN SYSTEM (MEDIUM)
---------------------------
Status  : ToolRegistry is formal but statically coded
Gap     : No dynamic loading, no community plugin API
Action  :
  1. Create ultron/plugin_loader.py with discover_plugins()
  2. Scan ~/.ultron/plugins/*.py on startup
  3. Each plugin defines class extending ToolDefinition or ModelProvider
  4. Auto-register into ToolRegistry / ProviderRegistry
  5. Document plugin API in ULTRON.md
  6. Add /plugins command to list active plugins
Files   : ultron/plugin_loader.py (new), ultron/tool_registry.py, ultron/repl.py
Priority: MEDIUM — enables community contributions

B2. EVIDENCE CONFIDENCE SCORES (MEDIUM)
-----------------------------------------
Status  : 4-tier evidence tagging (Observed/Verified/Inferred/Not verified)
Gap     : No numeric confidence, hard to prioritize what needs human review
Action  :
  1. Add confidence: float = 1.0 field to TaskEvidence dataclass
  2. VERIFIED by command exit 0 → confidence 1.0
  3. INFERRED by model → confidence 0.5
  4. NOT_VERIFIED → confidence 0.2
  5. Show in task summary: [Inferred 0.5] auth flow works as expected
Files   : ultron/task.py
Priority: MEDIUM — improves transparency

B3. REFACTOR GUARD AUTO-CHECK (MEDIUM)
---------------------------------------
Status  : RefactorGuard exists in analyzer.py, auto-triggers on refactor keywords
Gap     : Only checks callers, does not automatically run focused tests
Action  :
  1. After refactor task completes, auto-run: test command filtered to related tests
  2. If tests fail, set task status = BLOCKED, show /why output
  3. Add /refactor-check command for manual pre-refactor validation
Files   : ultron/analyzer.py, ultron/agent.py, ultron/repl.py
Priority: MEDIUM

B4. CONTEXT-AWARE PROVIDER ROUTING (MEDIUM)
---------------------------------------------
Status  : Smart routing exists in get_model_for_task() but not wired to task
Gap     : Same model used for all operations regardless of complexity
Action  :
  1. For lightweight ops (repo map, log summary, commit message): use fast model
  2. For complex ops (feature planning, debugging): use strong model
  3. Expose in /model-info which model handles which task type
  4. Let user configure routing in .ultron.toml [routing] section
Files   : ultron/providers/registry.py, ultron/agent.py, ultron/analyzer.py
Priority: MEDIUM
